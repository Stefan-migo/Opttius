# Proposal: fix-supabase-typed-clients

## Intent

3,122 TypeScript errors, 54% (1,691) are TS18046 — "'x' is of type 'unknown'". Root cause: 12 factory functions + middleware.ts create Supabase clients without the `<Database>` generic. Supabase v2 defaults to `GenericSchema` where every Row is `Record<string, unknown>`. Adding `<Database>` eliminates ~1,141 errors (67% of TS18046) with no runtime changes.

## Scope

### In Scope
- Add `<Database>` generic to all 12 factory functions in `src/lib/supabase/` and `src/utils/supabase/`
- Add `<Database>` generic to 2 direct `createClient` calls in `src/middleware.ts`
- Add ESLint `no-restricted-imports` rule blocking direct `@supabase/ssr` / `@supabase/supabase-js` imports outside wrapper files
- Verify TS18046 count drops from 1,691 to ~550 via `npx tsc --noEmit`

### Out of Scope
- Remaining ~550 TS18046 (catch blocks, request.body, deliberate `unknown`) — separate change
- Other TS error categories (TS2322, TS2345, etc.)
- Merging or deduplicating `src/lib/supabase/` and `src/utils/supabase/` parallel hierarchies

## Capabilities

No application capabilities change — pure type infrastructure fix.

- **New**: None
- **Modified**: None

## Approach

1. **Add `Database` import** to each factory file missing it (10 of 12 already need it; `server.ts` in both dirs already imports but doesn't use)
2. **Add `<Database>` generic** to every `createBrowserClient()`, `createServerClient()`, `createClient()` call — this is a single-param-type addition
3. **Fix `middleware.ts`**: add generic to both `createServerClient()` and `createClient()` calls (bypass direct imports)
4. **ESLint guard**: expand `no-restricted-imports` to block `@supabase/ssr` and `@supabase/supabase-js`, allowing only the typed wrappers via `allowImportPaths` pattern
5. **Verify**: `npx tsc --noEmit` confirms TS18046 drop

## Risks

| Risk | Likelihood | Mitigation |
|------|------------|------------|
| ESLint rule blocks legitimate direct imports in test files | Low | Test overrides already exist in `.eslintrc.json`; add `@supabase/ssr` exclusion if needed |
| Consumer depends on `unknown`-typed rows from untyped client | Very Low | No runtime change — pure TS narrowing; compile breaks are correct |
| Database type is out of sync with actual schema | Low | Generated by `supabase gen types`; regeneration before merge ensures correctness |

## Rollback Plan

Revert the PR. Every change is isolated to type imports and generic parameters — zero data impact, zero runtime behavior change.
